# 企业级智能诊断产品路线图

## 业务场景与指标

首个可量化场景为生产环境 API 延迟、错误率、资源耗尽和发布回归。每次诊断记录以下指标：

- MTTD：从告警产生到开始诊断，目标小于 2 分钟。
- MTTR：从诊断开始到给出可执行方案，目标小于 10 分钟。
- 证据覆盖率：结论关联至少一条真实证据的比例，目标不低于 95%。
- 自动化成功率：无需人工补充信息即可完成诊断的比例，目标不低于 70%。
- 误报率：人工复核后根因不成立的比例，目标低于 15%。
- 成本：每次诊断 Token、工具调用次数和外部 API 成本，按租户统计。

## 分阶段验收

### P0：可追踪基础（已落地）

- 请求 ID、租户 ID、用户 ID 和角色上下文。
- 结构化审计事件，默认脱敏，不记录完整提示词和敏感内容。
- 可配置审计开关、并发任务上限和模型提供商配置。

### P1：安全与控制面

- OIDC/JWT 身份认证，拒绝仅凭请求头声明身份。
- RBAC：诊断查看、知识库管理、工具调用、审批执行分离授权。
- 工具注册表：每个工具声明风险等级、所需权限、超时、重试和幂等性。
- 高风险工具进入人工审批队列，审批、执行、验证全部写入审计链。

### P2：可靠性与规模化

- 异步任务队列、持久化状态、幂等键和指数退避重试。
- 多租户向量库分区与文档 ACL 过滤，禁止跨租户检索。
- API、Worker、MCP 网关水平扩展；健康检查区分存活和就绪。
- 限流、熔断、超时和预算阈值，避免模型或工具失控。

### P3：智能质量与运营闭环

- 三层记忆：会话记忆、租户工作记忆、脱敏共享事故记忆。
- 诊断评测集、人工反馈、根因准确率和证据覆盖率看板。
- 模型路由与热切换：按任务、成本、延迟和可用性选择模型，并记录版本。
- 人工接管、交接班、Runbook 复用和事故复盘回写知识库。

## 安全边界

当前 `AUTH_ENABLED=false` 时，`X-Tenant-ID` 等请求头只用于开发环境上下文追踪，不能视为认证结果。开启后使用 HS256 JWT 过渡验证；正式生产仍建议接入 OIDC/JWKS，并轮换 `AUTH_SECRET`。
