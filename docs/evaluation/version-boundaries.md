# 四版本能力边界与消融约束 v1.0

## 固定条件

四个版本使用完全相同的模型及版本、系统提示词、temperature、上下文窗口、输入样本、
结构化输出协议、最大步骤数、超时、重试策略和安全策略。所有外部工具读取同一份冻结
fixture，禁止访问实时网络。版本之间不得同时修改提示词或模型参数。

## 版本定义

| 版本 | 新增的唯一变量 | RAG 上下文 | MCP 工具 | 动态重规划 |
|---|---|---:|---:|---:|
| V0 Core | 基线 | 否 | 否 | 否 |
| V1 RAG | 相对 V0 仅增加冻结的 RAG 检索上下文 | 是 | 否 | 否 |
| V2 MCP | 相对 V1 仅增加 MCP 日志/指标工具 | 是 | 是 | 否 |
| V3 Replan | 相对 V2 仅增加执行后动态重规划 | 是 | 是 | 是 |

### V0 Core

使用固定 Planner → Executor 流程；Planner 仅依据 incident 与题面 observations 生成一次
计划，Executor 不调用外部工具，执行后直接生成结构化结果。不得注入知识库内容。

### V1 RAG

执行流程与 V0 完全相同。唯一变化是输入中加入由冻结检索器返回的 Top-K 运维知识片段。
检索器版本、索引、Top-K 和返回顺序固定；RAG 不作为 Agent 可调用工具。

### V2 MCP

执行流程、RAG 和提示词与 V1 相同。唯一变化是 Executor 可调用冻结的 MCP 日志与指标
工具；仍只执行初始计划，不允许根据工具结果新增、删除或重排步骤。

### V3 Replan

工具、RAG 与 V2 完全相同。唯一变化是每个执行步骤后启用 Replanner，可根据已获得证据
调整剩余计划；总体步骤与工具调用仍受样本预算约束。

## 禁止的混杂变量

- 不同版本使用不同模型、模型快照或采样参数；
- 为某个版本单独修改提示词、Schema、重试次数或超时；
- 使用不同的 RAG 索引、MCP fixture 或工具响应；
- 仅为失败版本人工补充上下文；
- 在看到 sealed_test 结果后选择性删除样本。

每次正式运行必须保存模型标识、代码提交、数据集哈希、配置哈希及工具 fixture 哈希。
