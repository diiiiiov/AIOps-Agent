# 五版本能力边界与对比约束 v2.0

## 固定条件

五个版本使用相同的数据集、结果协议、采样参数、超时、重试策略、安全策略、RAG
索引和冻结工具 fixture，禁止访问实时网络。每次运行必须绑定模型快照、提示词、配置、
数据集和 fixture 的哈希。

## 版本定义

| 版本 | 体系 | RAG | MCP | 动态重规划 | 多 Agent |
|---|---|---:|---:|---:|---:|
| V0 Core | 单 Agent 基线 | 否 | 否 | 否 | 否 |
| V1 RAG | V0 + 冻结检索上下文 | 是 | 否 | 否 | 否 |
| V2 MCP | V1 + 固定工具计划 | 是 | 是 | 否 | 否 |
| V3 Replan | V2 + 执行后动态重规划 | 是 | 是 | 是 | 否 |
| V4 AIOps Team | Supervisor + 日志/监控/知识专业 Agent + 交叉验证 | 是 | 是 | 否 | 是 |

V0–V3 是逐项能力消融链，可以把相邻差异解释为新增能力的效果。V4 对应当前产品
架构，是对 V3 的候选架构比较：它以并行专业分工和 Supervisor 仲裁替换串行 Replan，
因此 `V3 → V4` 的差异不得表述为单一变量的因果效果。

## V4 协作轨迹要求

每个 case 必须记录 `log`、`monitor`、`knowledge` 三个隔离分支的状态、候选根因、
证据 ID 和分支耗时，并记录 Supervisor 是否完成交叉验证、识别的冲突数以及三个分支
的 wall-clock 耗时。缺失分支、重复分支或未执行交叉验证会被结果校验器拒绝。

专业 Agent 只能获得其领域证据；知识分支的历史模式不能当作现场证据。Supervisor
必须看到所有成功和失败分支，按证据权重仲裁，不得用多数票替代交叉验证。

## 禁止的混杂变量

- 同一对比中使用不同模型快照或采样参数；
- 为某版本单独修改结果 Schema、重试次数、安全策略或超时；
- 使用不同的 RAG 索引、MCP fixture 或工具响应；
- 向 V4 专业分支泄漏 oracle 标签或其他专业域的隐藏证据；
- 在查看 sealed test 结果后选择性删样本。

如果生产环境为 Supervisor 单独配置更强模型，应作为独立的“异构模型 Team”实验报告，
不能与固定同模型的 V0–V4 主对比混合。
