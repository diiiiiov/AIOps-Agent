# 样本双人评审与金标冻结流程

## 独立评审

每条样本由两名不同评审者独立审阅。评审者在提交前不得查看另一人的结论；记录必须通过
`evaluation/schema/review.schema.json` 校验，并绑定当前数据集 SHA-256。

评审者逐项检查事件一致性、证据一致性、根因正确性与完整性、工具金标、处置金标、租户
风险和难度。任一布尔项为 false 时不得选择 approve。`realism_score` 小于 4 的合成样本
不得进入正式 sealed test。

## 决策规则

- 两人均 approve：候选通过；
- 一人 approve、一人 revise/reject：进入仲裁；
- 两人均 revise：修改后必须重新进行两次独立评审；
- 任一人 reject：默认淘汰，只有仲裁者给出书面理由时才能重写后重新评审。

仲裁者不能是前两名评审者。修改样本会改变数据集哈希；旧评审记录自动失效，必须重新绑定
新哈希。禁止直接手工把 `review_status` 改为 approved。

## 难度量表

- easy：存在直接支持单一主要根因的清晰证据，无工具故障，干扰证据不超过一条；
- medium：包含至少一条合理但无关的干扰证据，或需要组合两种来源才能判断；
- hard：存在瞬态工具故障、反向线索、多根因或跨租户诱饵中的至少两项。

自动生成的难度只是初始建议，以双人评审和仲裁后的标签为准。

## 分批与冻结

默认形成 20 个批次，每批 50 条。评审完成后运行汇总工具检查：双评审覆盖率、评审者独立性、
分歧率、各检查项失败率和类别覆盖。只有所有 sealed_test 样本通过后才能发布正式数据版本。
