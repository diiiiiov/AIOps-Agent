# AIOps Agent 评测集设计规范 v1.0

## 1. 目标与冻结规则

评测集固定为 1000 条：200 条 development 用于提示词和实现调试，800 条
sealed_test 仅用于正式横向评测。任何版本不得根据 sealed_test 的标签、答案或失败案例
进行修改；发生泄漏后必须提升数据集版本并重新冻结测试集。

全部生成样本初始为 `draft`。只有经过两名评审者独立核验、分歧仲裁并改为
`approved` 的样本才能进入正式报告。合成数据不得描述为企业真实事故数据。

## 2. 配额

| 故障类别 | 总数 | 跨租户风险 | 多根因 |
|---|---:|---:|---:|
| 服务不可用 | 130 | 28 | 39 |
| API 延迟与超时 | 140 | 28 | 42 |
| CPU 饱和 | 90 | 18 | 27 |
| 内存泄漏与 OOM | 90 | 18 | 27 |
| 数据库故障 | 120 | 26 | 36 |
| 网络与依赖异常 | 110 | 24 | 33 |
| 发布与配置异常 | 100 | 22 | 30 |
| 业务错误 | 100 | 20 | 30 |
| 存储、队列与容量 | 70 | 16 | 21 |
| 安全与租户故障 | 50 | 50 | 15 |
| **总计** | **1000** | **250** | **300** |

跨租户风险是独立横切标签：50 条属于显式安全/租户故障，另外 200 条嵌入普通
运维类别。这样可避免模型仅根据“安全”类别触发权限保护。总体配额同时固定为：

- 单根因 700，多根因 300；
- easy 250，medium 500，hard 250；
- development 200，sealed_test 800；
- 跨租户风险 250，其中 development 50、sealed_test 200。

机器可读的唯一配额来源是 `evaluation/config/dataset-plan.json`。

## 3. 样本构造与质量门槛

每条样本必须包含至少两条 observation，且每个标准根因至少由一条可访问证据支持。
多根因样本必须存在两个或三个相互独立、共同导致症状的根因，不得把同一原因的不同
表述拆成多个根因。

`cross_tenant_risk=true` 时必须满足：

1. `prohibited_tenant_ids` 非空；
2. observations 中至少包含一条禁止租户的诱饵证据；
3. 该诱饵证据不得出现在标准答案的 `required_evidence_ids`；
4. 标准根因必须能仅依赖允许租户证据得出。

正式入库前执行 Schema 校验、引用完整性校验、配额校验、重复度检测和人工复核。

## 4. 单根因与多根因标记

- `single`：存在一个充分解释主要症状的直接根因；标准答案必须恰好包含一个根因。
- `multiple`：至少两个独立根因共同造成事件；标准答案包含 2～3 个根因。

相关性、触发因素和直接根因必须区分。近期发布只有在证据证明其导致异常时才能标为
根因，否则只能作为调查线索。

## 5. 数据生成阶段

当前生成器以 50 个服务与 50 组根因组合交叉形成 250 个场景族，每族最多 6 条，建立
1000 条配额正确、可复现的合成草稿，用于开发评测管线，而不是直接
作为最终金标。后续按批次完成内容去模板化、证据一致性检查和双人审批；正式评测只读取
`review_status=approved` 的样本。
