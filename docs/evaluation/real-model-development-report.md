# 真实模型开发集评估报告

评估日期：2026-07-23  
模型：`deepseek-chat`  
评估范围：200 条 development 样本，V0–V3 四版本，共 800 个 case-version 结果  
报告性质：开发集横向评估，不等同于密封测试集上的正式验收

## 1. 评估结论

在相同模型、样本、根因分类表、基础提示词和冻结工具夹具下，动态工具选择与重规划版本 V3 的效果最好：根因 F1 为 0.973，根因完全匹配率为 0.910。V3 相比固定工具计划版本 V2 的根因 F1 提升 0.524，95% 聚类 bootstrap 置信区间为 `[0.457, 0.590]`；根因完全匹配的 Holm 校正 McNemar `p=3.02e-26`。

代价是 V3 的平均 token 数、工具调用数和延迟明显增加。V3 的 P95 延迟为 7.73 秒，200 条成本为 0.6935 美元；V2 分别为 2.80 秒和 0.2768 美元。因此，V3 适合准确性优先的复杂诊断，V2 更适合作为低成本或低延迟路径，但 V2 当前准确率仍不足以单独承担自动闭环处置。

V0 到 V1 的提升很小且未达到统计显著：根因 F1 差值 0.022，95% CI 为 `[-0.002, 0.048]`，根因完全匹配 Holm 校正 `p=1.0`。这说明当前类别级 RAG 内容本身不能替代现场工具证据。

## 4. 关键切片

V2 在 API 延迟/超时、CPU 饱和、数据库三类场景的根因 F1 分别只有 0.071、0.093、0.167，是后续优化重点。V3 的最低类别是数据库，根因 F1 为 0.850；其余类别均不低于 0.962。

V3 对单根因样本的根因 F1 为 0.979，对多根因样本为 0.959，说明多根因场景仍略难，但没有出现明显失效。V3 平均调用 5.10 次工具，高于提示词期望的三次左右，后续应增加显式调用预算与去重约束。

## 5. 可复现性与有效性边界

- 四个版本使用同一模型 ID、开发集、全局根因分类表和基础输出协议；能力差异按版本配置限定为 RAG、MCP 和动态重规划。
- 模型调用为真实远程 API 调用；MCP 工具响应来自冻结评测夹具，而非在线生产系统，目的是保持消融变量和证据一致。
- 数据集 SHA-256 为 `3b05177b805bc0a8d4200e3adeabfb0c5eed4c320488ef646857877e77fb3768`，运行清单绑定了数据、版本配置、结果 Schema、提示词、RAG、重试和安全策略哈希。
- 提供方仅返回模型别名 `deepseek-chat`，没有不可变模型快照 ID。因此该结果可在本项目内追溯，但不能证明未来同名模型一定产生相同输出。
- 本轮使用 development 样本，允许用于调试和选型。对外发布最终数字前，应冻结候选实现，并在 800 条 sealed 样本审核通过后执行一次不调参的 formal 评测。
- 当前样本与工具证据为合成评测资产。报告支持工程消融结论，不应直接外推为真实生产故障恢复率或业务收益。

## 6. 建议

1. 保留 V3 作为高准确率路径，为工具调用增加硬预算、等价调用去重和提前停止条件，优先降低延迟与成本。
2. 若需要分层路由，可仅把 V2 用于低风险、证据模式明确的类别；数据库、API 超时和资源饱和类继续进入 V3 或人工接管。
3. 对 sealed 集完成双人审核、冻结模型别名/日期和所有哈希后，再执行正式评测；不得根据 sealed 结果回调提示词。
